# DocuMind AI

**AI-Enabled Document Management and Intelligent Semantic Search System**

DocuMind AI is a locally run document management application that extracts and indexes text from uploaded documents. It combines semantic retrieval, document categorization, concise source-grounded answers, and browser-based voice input and output in a lightweight web interface.

## 1. Project Overview

DocuMind AI helps users organize a collection of documents and find relevant information by meaning rather than relying only on exact keyword matches. The application has a static HTML/CSS/JavaScript frontend and a Python FastAPI backend. Uploaded files, document metadata, text chunks, and embeddings are stored locally.

## 2. Problem Statement

As document collections grow, it becomes harder to organize files consistently and locate a passage that answers a particular question. Filename-based browsing and exact-word searches can miss relevant material when a query uses different wording from the document.

## 3. Proposed Solution

DocuMind extracts readable text from PDF, DOCX, and TXT files, splits it into chunks, and represents those chunks as sentence embeddings. Users can search by semantic similarity or ask a question. The assistant selects relevant document sentences and returns them with source references; it reports when the available documents do not meet the relevance threshold.

## 4. Key Features

- Upload PDF, DOCX, and TXT documents.
- Extract text and divide it into chunks for indexing.
- Create semantic embeddings using the `all-MiniLM-L6-v2` Sentence Transformers model.
- Search document content by semantic similarity, with page references, relevance scores, snippets, and expandable text.
- Automatically assign a category and extract tags for each uploaded document.
- Filter the document list by category.
- View a document overview, key points, metadata, and reading statistics.
- Ask questions and receive concise answers grounded in indexed document text.
- Detect when no retrieved passage reaches the configured relevance threshold.
- Use browser speech recognition to enter questions and browser speech synthesis to listen to answers.
- Delete documents from the document list.

## 5. How the System Works

1. A user uploads a PDF, DOCX, or TXT file through the frontend.
2. The backend extracts text. PDF page numbers are retained; DOCX and TXT content are indexed as page 1.
3. Extracted text is split into chunks of up to 500 words.
4. DocuMind generates an embedding for each chunk and stores the chunk, page number, and embedding in SQLite.
5. The document is categorized and tagged, then its metadata is stored with the file information.
6. Search and question requests are embedded and compared against stored chunk embeddings. Results are ranked by cosine similarity.
7. The frontend displays matching content, source details, answers, or a missing-knowledge message.

## 6. AI/Semantic Search Functionality

Semantic search uses the `all-MiniLM-L6-v2` model from `sentence-transformers` to encode text. The backend compares the query embedding with stored document-chunk embeddings using cosine similarity, then returns the highest-scoring matches that meet the threshold. The search API defaults to a threshold of `0.30` and a limit of 5 results; the backend clamps the requested limit to the range 3–5 and may return fewer results if fewer candidates meet the threshold.

Each search result includes the filename, page, similarity percentage, a query-relevant snippet, and the full chunk text. This is embedding-based retrieval over the user's indexed documents; the project does not call an external generative AI service.

## 7. Missing Knowledge Detection

The question-answer endpoint checks the best retrieved similarity score against a configurable threshold, which defaults to `0.35`. If there are no matching chunks or the best score is below that threshold, the response sets `knowledge_found` to `false`, includes the best score and threshold, and suggests uploading a relevant document or rephrasing the question. Otherwise, it selects up to three relevant sentences from retrieved chunks and returns their filename and page as sources.

The answer is assembled from document text; it is not generated by an external large language model.

## 8. Voice Output

Voice features are implemented in the browser, not by a backend speech service:

- **Voice input:** Uses the browser's Web Speech `SpeechRecognition` API (including the `webkitSpeechRecognition` implementation where available) to transcribe an English question into the input field.
- **Voice output:** Uses the browser's `SpeechSynthesis` API to read an answer aloud. Playback controls support play, pause, resume, stop, and replay.

Voice API availability depends on the browser. Text input and displayed answers do not require voice support.

## 9. Document Organization

On upload, the backend compares an embedding of the document text against predefined category profiles. The available categories are Artificial Intelligence, Software Engineering, Education, Research, Programming, Business, and Other. It also extracts up to five tags using frequent words and word pairs. Users can filter the document list by category and open a summary view with file details, overview, key points, page/chunk counts, and estimated reading time.

## 10. Technology Stack

- **Backend:** Python, FastAPI, Uvicorn, Pydantic, `python-multipart`
- **Document text extraction:** `pypdf` for PDF and `python-docx` for DOCX; Python file I/O for TXT
- **Embeddings and similarity:** Sentence Transformers (`all-MiniLM-L6-v2`) and NumPy
- **Persistence:** SQLite via Python's built-in `sqlite3` module
- **Frontend:** HTML, CSS, and vanilla JavaScript
- **Voice:** Browser Web Speech APIs (`SpeechRecognition` / `webkitSpeechRecognition` and `SpeechSynthesis`)

## 12. Installation and Setup

### Prerequisites

- Python 3 installed and available as `py` or `python` on your `PATH`.
- A modern browser. A browser with Web Speech API support is required for voice features.
- Internet access on the first backend start so Sentence Transformers can download `all-MiniLM-L6-v2` if it is not already cached.

From the project root, create and activate a virtual environment, then install the backend requirements.

**Windows PowerShell:**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
```

**macOS/Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
```

## 13. How to Run Backend

Start the backend from the `backend` directory. Running it there ensures the relative `uploads/` and `documents.db` paths resolve inside `backend/`.

```bash
cd backend
python -m uvicorn main:app --reload
```

The API will be available at `http://127.0.0.1:8000`. FastAPI's interactive API documentation is available at `http://127.0.0.1:8000/docs`.

## 14. How to Run Frontend

In a separate terminal, from the project root:

```bash
cd frontend
python -m http.server 5500
```

Open `http://127.0.0.1:5500` in a browser. The frontend is static and calls the backend at `http://127.0.0.1:8000`; make sure the backend is running as well. The backend currently allows cross-origin requests.

## 15. API Features

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/` | Backend welcome and version response. |
| `GET` | `/api/status` | Application status and enabled feature indicators. |
| `GET` | `/api/health` | Health status; same handler as `/api/status`. |
| `POST` | `/api/upload` | Upload and index a PDF, DOCX, or TXT file (`multipart/form-data`, field `file`). |
| `GET` | `/api/documents` | List documents; optionally filter with `?category=Research`. |
| `GET` | `/api/documents/{document_id}/summary` | Return document metadata, overview, key points, and statistics. |
| `DELETE` | `/api/documents/{document_id}` | Delete the document record and its indexed chunks. |
| `POST` | `/api/search` | Search indexed content by semantic similarity. |
| `POST` | `/api/ask` | Answer a question from indexed content or report that relevant knowledge was not found. |

Example search request:

```json
{
  "query": "How does machine learning work?",
  "limit": 5,
  "threshold": 0.3
}
```

Example question request:

```json
{
  "question": "What does the document say about machine learning?",
  "threshold": 0.35
}
```

## 16. Example Usage

1. Start the backend and frontend using the commands above.
2. Open the frontend and go to **Documents** to upload a PDF, DOCX, or TXT file.
3. View the automatically assigned category and tags, or filter the document list by category.
4. Open a document summary to review its overview and key points.
5. Go to **Semantic Search** and enter a topic or question to see ranked snippets and source pages.
6. Go to **AI Assistant** to ask a question about uploaded content. Use the microphone where supported, or type the question. Read the source-grounded answer or listen to it with the voice controls.
